Scope and behavior

The server owns authoritative online match state. EntryPollGroup handles initial connections; PlayerPollGroup handles established players. Transport is abstracted by IServerTransport with GNS and optional WebRTC implementations. The scripting engine is initialized and constructed by the application; this diagram does not claim that every gameplay rule is script-driven. Lobby metadata still contains placeholder fields in LobbyClient.

Online match flow

  1. The client connects and sends its hello. The native path validates the hello in EntryPollGroup and hands the connection to PlayerPollGroup. The WebRTC path validates the hello in GameServer. Player session setup assigns a soldier and sends the initial match state. Game server · Player sessions
  2. The client sends soldier input while predicting locally. The server input handler passes input to the command queues, where it can be selected for the corresponding simulation tick. Server input handler
  3. ServerRuntime polls networking, selects player inputs and drains simulation commands, then advances the authoritative world. It records applied input sequences, routes simulation events and broadcasts authoritative state. Server runtime
  4. The client handles the authoritative soldier update. When reconciliation requires a correction, the handler applies the authoritative state and replays the relevant predicted inputs after the server tick. Client reconciliation
