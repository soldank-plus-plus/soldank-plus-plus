Scope and behavior

The game client and server each link shared_lib and have separate in-memory worlds. client_lib provides the front end; server_lib provides server services; soldank_server_scripting isolates daScript integration. No database service is identified in this runtime. Asset download through CPM is a build-time concern.

Build and runtime variants

  • The native client connects via GameNetworkingSockets. The Emscripten client uses WebRTC data channels, with HTTP signaling at /webrtc/offer and /webrtc/candidate. The game server hosts those endpoints through its libdatachannel transport when built with BUILD_WEBRTC_SERVER_TRANSPORT.
  • The optional native movement_scenario_player links client_lib and movement_scenarios_lib. It can run interactively or export from the command line. Movement scenario tests also use movement_scenarios_lib. Build target selection · Scenario player
