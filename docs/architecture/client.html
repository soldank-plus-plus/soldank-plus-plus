Scope and behavior

NetworkingClient uses a platform connection implementation: native GameNetworkingSockets or the browser WebRTC bridge. NetworkEventDispatcher invokes client event handlers. Simulation events are routed to client presentation services; rendering and audio remain outside shared_lib. ClientRuntime is a mode and input-context policy object, not the simulation loop.

Client loop and mode transitions

Application wires input, world-update and rendering callbacks into the world loop. The native client drives frames through the native loop and the browser client through Emscripten. Each iteration polls networking in online mode and routes input in the active context. Before a world update, PlayerController applies controls for the local soldier.

  • Local matches advance the client world and use simulation events for presentation.
  • Online matches send local input through NetworkClientSession and predict the local soldier while the server advances the authoritative match. Follow an online input through the server and back.
  • Editing starts with the world paused. EditorSession switches between editing and play-testing, and ClientRuntime updates the input context to match. Starting a play-test resumes the world. Ending it pauses the world and restores the editable map. Editor session · Platform loop
